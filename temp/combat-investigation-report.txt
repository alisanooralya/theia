3. TURN / ROUND SYSTEM (DOMAIN)
--------------------------------------------------------------------------------

- Satu round = 1 serangan player + 1 serangan boss (boss menyerang hanya jika
  masih hidup setelah serangan player) - domain.js:126-148.
- Player SELALU menyerang duluan; tidak ada SPD di codebase; tidak ada initiative roll.
- MAX_ROUNDS = 30 (domain.js:12). Battle tipikal: boss Easy ~500 HP mati beberapa
  round; Hard 4000 HP biasanya mencapai cap 30 round vs player lemah.
- Combat disimulasikan INSTANT - satu synchronous for loop. "Durasi" adalah
  VIRTUAL CLOCK: turnNow = startTime + i * 1000 (1 detik per round, domain.js:118)
  hanya untuk mem.drive durasi/cooldown pasif Card.
- Kondisi berakhir: boss.hp <= 0 (menang), player.hp <= 0 (kalah), atau 30 round
  -> won = boss.hp <= 0 = false (round-limit = kekalahan player, domain.js:153).
- Setelah battle: cardBattleState.reset(), statsModel.setHp(jid, player.hp) -
  HP dipersist ke DB.
- PvP: MAX_ROUNDS = 10, maks 4 attack/round (attack + kemungkinan counter tiap
  sisi), round-limit -> pemenang by remaining HP atau draw (battle.js:288-297).

4. DAMAGE CALCULATION
--------------------------------------------------------------------------------

Domain calcDamage (domain.js:47-63) - core identik dengan PvP _attack (battle.js:353-425):

  attackerStats = cardTurnStats(attacker, now)     // stack ATK/DEF Lena live
  defenderStats = cardTurnStats(defender, now)
  base = max(1, attackerStats.atk - floor(defenderStats.def / 2))
  vary = floor(base * 0.2)
  dmg  = base + floor(random() * vary * 2) - vary   // variance +/-20%
  if random() < critRate: dmg = floor(dmg * cdm)    // critRate clamped 0-0.95; cdm = 2.0 (ameris: 2.5 window)
  dmg = applyOutgoingCardDamage(dmg, attacker, now) // Girgas/Daisy/Support dmg x, min 1
  dmg = applyIncomingCardDamage(dmg, defender, now) // Iron Will/Daisy taken x, min 1

Modifier khusus PvP (battle.js, TIDAK ada di Domain): Momentum (+4%/stack,
Overdrive x1.25 di 3 stack), Powerful Hit (12% pada non-crit, x1.35), Block
(chance def/(def+200) capped 0.18, non-crit, x0.45), Counter (12%, base x 0.7,
bisa crit).

- Minimum damage: 1 (via Math.max di base dan card-damage applier).
  TIDAK ada maximum/cap damage.
- Boss -> player: formula sama; boss tanpa cardBattleState sehingga step
  outgoing card-nya no-op dan getCardCdm(boss) = 2.0; boss default critRate 0.05
  (domain.js:112).
- Kehilangan HP player dipersist; pemenang heal 20% max HP hanya di PvP
  (battle.js:107-114).

5. CARD INTEGRATION
--------------------------------------------------------------------------------

Hook berada di src/features/rpg/card.js:

| Hook | Dipanggil di | Efek | Dependency timing |
|---|---|---|---|
| cardTurnStats (:361) | sebelum base damage | Lena: ATK/DEF x(1+0.1*stacks) | stack expire 5s virtual time; cooldown trigger 4s |
| getCardCritRate (:391) | setelah base dmg | Critical Eye +5%, Ameris +10% dalam window 4s | window setiap hit ke-3, cooldown 6s |
| getCardCdm (:384) | dengan crit | 2.0 base; Ameris 2.5 dalam window | window sama |
| applyOutgoingCardDamage (:327) | setelah crit | Girgas +10%/stack (max 2, 8s), Daisy +10-40% by tier HP, Raid Emblem +5% | virtual time / rasio HP saat ini |
| applyIncomingCardDamage (:345) | setelah outgoing | Iron Will -5%, Daisy taken x0.8-0.9 by tier HP | rasio HP saat ini |
| onHitDealt/onHitReceived (:216/239) | setelah tiap attack | advance counter stack Girgas/Ameris/Lena | hit count + virtual time |

State IN-MEMORY ONLY (CardBattleState dibuat per battle, reset() di akhir) -
tidak ada yang dipersist. Semua pasif didrive oleh VIRTUAL CLOCK 1s/round,
sehingga secara natural kompatibel dengan simulasi turn-based mana pun; tidak
ada yang tergantung wall-clock waktu nyata. Path legacy fighter.cardModifiers
di fungsi-fungsi ini hanya dipakai oleh Raid 1.0 (getCombatModifiers tidak
punya pemanggil combat selain card.js sendiri).

9. RAID 2.0 REUSE POTENTIAL
--------------------------------------------------------------------------------

A. Langsung reusable:
   - artifactService.getPlayerStats(jid) - snapshot stat lengkap (memperbaiki
     partial stat loading atk-only Raid 1.0).
   - cardService.getBattleState(jid) + semua helper card.js (cardTurnStats,
     getCardCritRate, getCardCdm, applyOutgoing/IncomingCardDamage) - in-memory,
     time-driven, engine-agnostic.
   - simulateBattleAgainst(jid, enemy) sebagai engine "player vs custom boss"
     yang paling mendekati (Bounty sudah mengadaptasinya).

B. TIDAK sebaiknya direuse: DIFFICULTY/reward/drop artifact Domain; layer
   block/counter/momentum PvP (di-tune untuk duel 10 round, akan mendistorsi
   battle kontribusi 120 detik); mesin pending/confirm/state PvP (khusus
   player-vs-player); aturan round-limit-defeat Domain (Raid butuh damage,
   bukan win/loss); loop interval real-time 30s Raid 1.0.

C. Adapter yang dibutuhkan (kecil): builder fighter/boss yang memetakan
   getPlayerStats + buff + HP saat ini ke fighter shape, dan round-loop yang
   (a) menghitung TOTAL damage dealt, bukan hanya cek kill, (b) berhenti pada
   jumlah round yang memetakan ke 120 detik virtual time, (c) menulis
   kontribusi ke raid_participants.damage. simulateBattleAgainst sudah
   mengembalikan event per-round, tapi memutasi/mempersist HP player dan
   mengembalikan win/loss - varian Raid butuh sum total-damage (event sudah
   membawa dmg per player_attack, domain.js:128).

D. Bisakah Raid mensimulasikan battle 120 detik tanpa engine kedua? YA -
   virtual clock engine (startTime + i*1000, 1s/round) sudah memisahkan
   waktu simulasi dari waktu nyata. 120 detik virtual = ~120 round (atau
   pertahankan mapping 1-round=1s). Semua pasif card (durasi 8s/5s/4s,
   cooldown) bekerja pada virtual clock itu. Tidak ada dependency real-time
   di dalam core simulasi.

10. RECOMMENDED RAID BATTLE FLOW
--------------------------------------------------------------------------------

  .raid attack (join/attack)
  -> statsModel.ensure + cek HP>0 (pattern: domain.js:84-86)
  -> snapshot: artifactService.getPlayerStats + cardService.getBattleState + buff overlay
  -> build raid fighter {hp, max_hp, atk, def, critRate, cardBattleState}
  -> build boss fighter {hp: boss_hp, max_hp, atk, def, critRate}
  -> simulate round dengan virtual clock (reuse bentuk round-loop domain)
     akumulasi totalDamage dari event player_attack
  -> stop at: 120 detik virtual / HP player 0 / HP boss 0
  -> cardBattleState.reset()
  -> persist: damage participant += totalDamage; HP participant; HP boss
     (transaksi, pattern sql.begin: battle.js:103)
  -> return {totalDamage, rounds, playerFinalHp} untuk output pesan

Ini persis mirror simulateBattleAgainst, mengganti return win/loss + HP-only
dengan damage accounting - tanpa combat engine kedua.

11. IMPORTANT FINDINGS
--------------------------------------------------------------------------------

1. Dua engine, satu layer helper share: PvP (battle.js) dan Domain (domain.js)
   masing-masing berisi calcDamage/round-loop yang hampir identik; hanya fungsi
   card.js yang benar-benar shared. Raid 2.0 sebaiknya dibangun di atas varian
   Domain (sudah terbukti reusable oleh Bounty, bounty.js:137).

2. Combat sepenuhnya INSTANT, virtual-clocked (startTime + i*1000); semua pasif
   Card tergantung virtual time ini, bukan waktu nyata. Battle Raid 120 detik =
   ~120 round tersimulasi, tanpa loop real-time.

3. artifactService.getPlayerStats adalah pipeline stat tunggal (base + artifact
   + Main Card flat, buff dioverlay pemanggil) - aman direuse; catatan: pakai
   stats.max_hp sebagai base HP dan stat % di-scale dari base, bukan final stat.

4. HP DIPERSIST, tidak direstore: statsModel.setHp setelah tiap battle; Raid 2.0
   harus memutuskan persist HP player atau pakai model participant.hp terisolasi
   ala Raid 1.0.

5. Tidak ada stat SPD; player selalu menyerang duluan; round-limit di Domain =
   kekalahan (Raid butuh total damage).

6. Batas damage: min 1, tanpa cap max; crit rate hard-clamp 0-0.95; crit DMG 2.0
   (2.5 window Ameris); variance +/-20%; DEF dikurangkan pada setengah nilai.

7. State Card in-memory per battle (CardBattleState.reset() setelahnya) - tidak
   ada concern persistensi untuk Raid, tapi tidak boleh dishare antar battle
   concurrent user yang sama.

8. Raid 1.0 mengabaikan DEF dan stat parsial (getUserRaidStats hanya menghitung
   mainstat artifact atk/crit_rate, tanpa substat, HP tetap 2400) - reuse
   getPlayerStats memperbaikinya gratis.

9. Base stat tidak pernah bertumbuh (level-up tidak menyentuh stats;
   statsModel.updateEquipment adalah dead code) - progresi hanya dari artifact
   dan level Main Card.

10. Catatan inkonsistensi: default crit_rate 10 di definitions.js:46 tapi 5 di
    ALTER definitions.js:523 dan fallback getPlayerStats (artifact.js:490) -
    perlu diketahui sebelum balancing boss Raid.
